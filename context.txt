# 📄 RESUMEN DOCUMENTADO DEL PROYECTO DE ESCANEO POLIHC– DEFINICIÓN INICIAL

## 🎯 Objetivo General

Desarrollar un sistema de escaneo estructurado en **tres fases**:

1. **Conector local (Flask):** Controla el escáner físico (Toshiba e-STUDIO2822AM), gestiona el proceso de escaneo y envía las imágenes.
2. **Interfaz web (Django + Frontend):** El usuario controla el proceso desde la web, visualiza y edita las páginas escaneadas.
3. **Módulo OCR + IA + PostgreSQL:** Extrae información de los documentos finales y almacena los datos estructurados.

---

## 🧱 Arquitectura General

| Componente                      | Rol                                                                                    | Tecnologías                                                   |
| ------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| **Conector (Flask)**            | Se conecta al escáner vía TWAIN, captura páginas como WEBP (por defecto) o PNG (legacy), controla sesión | Python 32-bit, TWAIN, Flask                 |
| **Frontend + Backend (Django)** | Interfaz para gestionar el escaneo, mostrar imágenes, permitir edición y generar PDF/A | Django, HTML/JS (Drag & Drop, edición visual)                 |
| **OCR + IA + BD** *(fase 3)*    | Leer documentos finales y almacenar en PostgreSQL                                      | OCR (Tesseract local), IA (clasificación), PostgreSQL |

---

## 📌 Restricciones y Reglas Confirmadas

**Cada instancia del conector Flask controla 1 escáner físico.**
**Solo una sesión activa a la vez por escáner (bloqueo global con timeout de 20 minutos).**
**Si el escáner está ocupado**, el sistema debe reportarlo inmediatamente con código 409.
**Formato de imagen temporal:** **WEBP por página** por defecto (nombradas como `page_001.webp`, `page_002.webp`...). PNG legacy configurable.
**El conector NO genera PDF.** Django es responsable de la generación del PDF/A.
**Django recibe imágenes página por página** mediante polling y descarga HTTP.
**Si el usuario cancela, se borran TODAS las imágenes temporales** (endpoint `/cancel`).
**Limpieza automática programada**: Se ejecuta diariamente (configurable) para eliminar sesiones residuales.
**Timeout de inactividad**: Carpetas de sesión con > 20 minutos de inactividad se limpian automáticamente.
**Verificación con timeouts**: Endpoint `/check-scanner` responde en máximo 28 segundos incluso si el escáner está apagado/desconectado.
**Detección inteligente de hojas**: Verifica disponibilidad en ADF (7s timeout) y flatbed (28s timeout) antes de iniciar.
**Manejo de páginas en blanco**: Detecta y omite páginas blancas automáticamente.
**Se permite continuar escaneo**: Endpoint `/continue` permite agregar más páginas a la sesión activa.
**Soporte para modo flatbed y ADF**: El usuario puede elegir entre cristal o bandeja automática.
**Una vez confirmado, Django genera el PDF/A y lo almacena localmente.**
**Luego entrará OCR/IA para extracción de datos clínicos.**
**Se debe permitir agregar imágenes externas (radiografías, fotos) en el editor web.**
**Por decisión de la empresa, todo opera en modo local (sin VPS, sin Tailscale y sin acceso remoto).**

# Funcionalidades Implementadas

## 🎯 **API REST Completa**

### **Endpoints de Verificación**
- ✅ `GET /` - Estado del servicio Flask
- ✅ `GET /api/scan/check-scanner` - Verifica disponibilidad con timeouts diferenciados
  - **Timeouts**: ADF (7s), Flatbed (28s)
  - **Respuestas**: 200 (OK), 503 (No disponible), 504 (Timeout/Apagado)
- ✅ `GET /api/scan/check-feeder` - Verifica papel en bandeja ADF
- ✅ `GET /api/scan/status` - Estado del escaneo en tiempo real

### **Endpoints de Escaneo**
- ✅ `POST /api/scan/start` - Inicia nueva sesión de escaneo
  - Validación de parámetros (DPI, color, tamaño, rotación)
  - Verificación previa de hojas disponibles
  - Creación de carpeta de sesión única
  - Respuesta inmediata con `session_id`
- ✅ `POST /api/scan/continue` - Continúa escaneando en sesión activa
  - Permite agregar más páginas sin cerrar la sesión
  - Útil para escaneo por lotes
- ✅ `POST /api/scan/cancel` - Cancela escaneo y elimina archivos
  - Limpieza completa de la sesión
  - Liberación del bloqueo del escáner
- ✅ `POST /api/scan/finish` - Finaliza sesión y limpia archivos
  - Libera el escáner para otros usuarios
  - Elimina carpeta temporal después de confirmar

### **Endpoints de Recuperación de Datos**
- ✅ `GET /api/scan/pages` - Lista páginas de sesión activa
- ✅ `GET /api/scan/pages/<session_id>` - Lista páginas de sesión específica
- ✅ `GET /api/scan/download/<session_id>/<filename>` - Descarga imagen WEBP/PNG
  - Django usa este endpoint para obtener las imágenes

### **Endpoints de Limpieza**
- ✅ `POST /api/scan/run-cleanup` - Limpieza manual de sesiones residuales
- ✅ `DELETE /api/scan/cleanup/<session_id>` - Elimina carpeta de sesión específica

---

## 🔒 **Sistema de Bloqueo de Sesiones**

- ✅ **Bloqueo exclusivo**: Solo un usuario puede escanear a la vez
- ✅ **Timeout de sesión**: 20 minutos de duración máxima
- ✅ **Estado thread-safe**: Uso de `threading.Lock()` para prevenir race conditions, es para asegurar que no haya conflictos al acceder/modificar el estado de la sesión
- ✅ **Liberación automática**: Al finalizar, cancelar o por timeout
- ✅ **Validación de sesión activa**: Verifica que la sesión pertenezca al usuario correcto

---

## ⏱️ **Sistema de Timeouts**

### **Verificación de Escáner (check-scanner)**
```python
FEEDER_TIMEOUT = 7                    # ADF responde rápido
FLATBED_CONNECTION_TIMEOUT = 12       # Fase 1: conexión al cristal
FLATBED_SCAN_TIMEOUT = 28             # Fase 2: escaneo activo en cristal
```

### **Implementación con ThreadPoolExecutor**
- ✅ No usa `with` para evitar esperar threads bloqueados
- ✅ `executor.shutdown(wait=False)` abandona threads zombie
- ✅ Endpoint responde correctamente incluso si TWAIN se bloquea en C
- ✅ Tiempo total máximo: ~28 segundos (incluye timeout de verificación y overhead)

### **Códigos de Respuesta HTTP**
- **200**: Escáner disponible y listo
- **503**: Escáner responde pero sin hojas
- **504**: Timeout - escáner apagado/desconectado
- **409**: Sesión en uso por otro usuario
- **400**: Parámetros inválidos
- **500**: Error interno del servidor

---

## 🧹 **Sistema de Limpieza Automática**

### **Limpieza Programada**
- ✅ Se ejecuta diariamente a las **15:30** (configurable en `run_production.py` / `run_with_console.py`)
- ✅ Usa `threading.Timer` para programación asíncrona
- ✅ Se reprograma automáticamente después de cada ejecución

### **Criterios de Limpieza**
```python
timeout_minutes = 20  # Carpetas con > 20 min de inactividad
```
- ✅ Revisa fecha de modificación de carpetas de sesión para detectar inactividad y eliminar según inactividad
- ✅ Protege sesiones activas en progreso (no las elimina) al usar /continue
- ✅ Elimina carpetas huérfanas de sesiones expiradas
- ✅ Libera locks de sesiones residuales

### **Limpieza Manual**
- Endpoint `/run-cleanup` permite forzar limpieza
- Ejecuta en thread separado para no bloquear la API porque puede tardar en completarse, es decir , no espera a que termine la limpieza para responder al usuario
- Loguea advertencias si hay escaneo activo

## 📊 **Estrategia de Integración con Django**

### **Flujo Recomendado (Pull Strategy)**

```
1. Django → POST /api/scan/start
   ↓ Respuesta: {session_id: "session_123"}

2. Django → GET /api/scan/status (polling cada 2s)
   ↓ Loop hasta status: "completed" o "error"

3. Django → GET /api/scan/pages/{session_id}
   ↓ Respuesta: {pages: [{filename, page_number, full_path}]}

4. Django → GET /api/scan/download/{session_id}/{filename} (por cada página)
  ↓ Descarga WEBP/PNG y guarda en Django media folder

5. Usuario decide en el frontend:
   a) "Escanear más páginas" → Django → POST /api/scan/continue
      └─ Volver al paso 2
   
   b) "Ya terminé" → Django → POST /api/scan/finish
      └─ Flask limpia la sesión y libera el escáner

6. NO usar /cleanup/{session_id} salvo para limpieza manual de sesiones huérfanas
```

### **Ventajas del Pull**
- ✅ Django controla el flujo completo
- ✅ Manejo de errores más simple
- ✅ Reintentos automáticos si falla descarga
- ✅ Menos acoplamiento entre sistemas
